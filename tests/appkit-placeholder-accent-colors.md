# Qt-required placeholder and accent semantic roles

Apple documents [placeholderTextColor](https://developer.apple.com/documentation/appkit/nscolor/placeholdertextcolor) for placeholder text in controls/text views, and [controlAccentColor](https://developer.apple.com/documentation/appkit/nscolor/controlaccentcolor) as the current accent preference. Public documentation JSON Objective-C variants declare both class strong readonly NSColor properties (clean-room rung3). [Apple Dark Mode HIG](https://developer.apple.com/design/human-interface-guidelines/dark-mode) supplies adaptive-role/contrast guidance, not numeric fallback samples.

Primary upstream [Qt qcocoatheme.mm v6.11.2](https://github.com/qt/qtbase/blob/v6.11.2/src/plugins/platforms/cocoa/qcocoatheme.mm#L96) calls placeholder then accent during palette construction (lines96/101). An original source-name audit of its19 explicit/macro semantic color getters found these two missing here; this is closely related demand, not speculative wholesale API coverage. No Qt implementation is copied.

Both getters use the existing systemCatalogColor helper, which chooses a registered catalog backing before fallback and avoids the backend unknown-role path (currently logs/returns red). Placeholder uses that backing in Aqua; the existing semantic palette machinery deliberately selects the project dark value in DarkAqua/VibrantDark, even if a registered placeholder provider has a dark variant. Arbitrary registered placeholder-provider preservation across appearances is not claimed. Placeholder uses an original opaque neutral Aqua0.45 and DarkAqua/VibrantDark0.60 policy through the shared dynamic catalog backing; it remains subdued relative to semantic text and distinct from the surface. These are project fallback values, not native Apple samples. Opacity is an intentional design choice; the separate catalog-alpha prerequisite fixes the underlying opacity API rather than hiding it.

Accent uses an existing actual selectedControlColor fallback; current Linux backend supplies blue. A registered accent color/provider is retained, including its dynamic behavior, but no desktop accent-preference discovery/synchronization is implemented or claimed. It is not fabricated physical/current-user preference evidence. The helper/catalog preserves role identity and late provider use. Existing highlightWithLevel catalog behavior and broader Qt palette/native menu qualification are outside this getter addition.

Original appkit-placeholder-text-color.m: no args/NSApp/window, AppKit/CoreGraphics. Public selector/catalog identity, cache retained past creation pool, actual setFill and converted CGColor pixels, transparent/colored background checks with truthful opaque alpha, lower-emphasis readable contrast vs semantic surface/text, nested scopes and restoration without reconstruction. Explicit half-alpha content and non-System catalog controls remain unchanged. Original appkit-control-accent-color.m checks selector/role/cache lifetime, actual current backend selection fallback and real derived half-alpha pixels. The blue fallback assertion is current-backend-specific, not an Apple palette claim. Registered accent-provider preservation follows the existing source path; this original fallback fixture does not runtime-qualify that separate registration path. Compile-only appkit-semantic-role-headers.m checks direct public return types without fixture categories.

Coordinator placeholder parent baseline: missing getter, exit1 in1.618s, exact-prefix shutdown0 (logs/placeholder-color-before.json). Earlier unchanged KeePassXC reached that selector after display/theme initialization, exit134 in3.313s with unchanged executable hash/shutdown0; separate demand progress, not a working app claim. Catalog-alpha parent/candidate gates are documented separately. Coordinator accent parent baseline: missing public getter, exit1 in1.633s, exact-prefix shutdown0 (logs/control-accent-before.json). Combined candidate guest tests remain coordinator-owned; no global theme change, high-contrast completeness, alpha-archive roundtrip or actual UI acceptance is claimed.
