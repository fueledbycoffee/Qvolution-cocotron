# Actual graphics-font names before normalized CoreText descriptors

Original explicit-provider fixtures exposed a prerequisite: O2Font's two C copy-name getters both copied `_name`. Provider-loaded fonts never populated it, and named fonts stored the request spelling rather than the matched face identity. The original CoreText trait/name/descriptor probes therefore failed earlier input-identity checks and are not before proof of their later assertions. Only the original coordinator named-font descriptor probe separately reached its nil stub.

The focused CG-only before test uses actual glyph-count/units controls before requiring provider PostScript name. Coordinator observed this intended missing-metadata failure: exit1 in1.60078s with exact-prefix shutdown0, logs/cg-font-names-before.json. No AppKit or CoreText is linked in that test. No vendor crash cause is inferred.

Vendored public CGFont.h already declares both copy-name APIs (clean-room rung2). Apple's public [postScriptName](https://developer.apple.com/documentation/coregraphics/cgfont/postscriptname) and [fullName](https://developer.apple.com/documentation/coregraphics/cgfont/fullname) document the distinct metadata roles (rung3). Implementation uses existing open-source FreeType public interfaces, not Apple implementation expression: [FT_Get_Postscript_Name](https://freetype.org/freetype2/docs/reference/ft2-information_retrieval.html#ft_get_postscript_name), [SFNT names](https://freetype.org/freetype2/docs/reference/ft2-sfnt_names.html), and [FT_Get_PS_Font_Info](https://freetype.org/freetype2/docs/reference/ft2-type1_tables.html#ft_get_ps_font_info). The latter's strings belong to the face; all returned NSString values here own their copied contents. [Microsoft OpenType name-table specification](https://learn.microsoft.com/en-us/typography/opentype/spec/name) identifies nameID4 as the full name and specifies Unicode/Windows UTF16BE and platform-specific encoding distinctions. Only public open-source headers/interfaces and these primary documents were consulted.

C getters dispatch copyFullName/copyPostScriptName. The base methods preserve existing other-backend `_name` behavior; FreeType captures owned immutable metadata during initWithFace before publication; public copy getters never call FreeType. This avoids introducing lazy name-stream/PS-cache face mutations concurrently with rendering (FreeType permits only one thread at a time per face). Existing renderer face locking is not otherwise repaired or qualified. There is no current face-variation mutation API in this lane; future mutable face/name changes would need explicit invalidation. Checked CF creation returns nil on unsupported byte conversion without entering Foundation’s unchecked NSString mutable-copy path. FreeType helpers read actual face metadata without rewriting the requested `_name` label or introducing AppKit. SFNT strings use explicit byte lengths, reject empty/odd/unpaired-surrogate UTF16 and unsupported encodings, and support Unicode encoding IDs0..4 (not cmap-only variation IDs or unknowns), Windows Unicode/symbol and Macintosh Roman entries. Selection policy is explicit project behavior: first valid supported entry, overridden by an available Windows English-US Unicode entry. This is not native locale-matching equality. Missing supported SFNT full-name metadata remains nil, with no requested-label/family/style synthesis. Non-SFNT PostScript FontInfo full_name is copied when the public API supplies decodable UTF8; the original Type1 test qualifies an ASCII-named open URW font and rejects an original invalid-UTF8 FontInfo name variant, not every legacy 8-bit encoding or native font format.

Original tests:

- `coregraphics-font-names.m`: exact open DejaVuSans.ttf and DejaVuSans-BoldOblique.ttf arguments, actual CG metrics before expected PS/full identity, distinct names, immutable copy isolation and ownership after face/provider/pool destruction; named regular font additionally distinguishes request spelling from actual PS name. Expected open-font names were independently checked using host Fontconfig metadata queries.
- `make-font-name-vectors.py`: explicit open BoldOblique source only; original stdlib mutation of full-name records, keeping glyph payload and valid table/file checksums. Generates missing/odd UTF16/unpaired surrogate/unsupported Windows encoding/empty/unknown Unicode encoding/Unicode variation-selector encoding negatives, and supplementary Unicode/high-byte MacRoman positives and a conflicting fallback-vs-English preference vector. Ten variants are produced. No generated font bytes are committed.
- `coregraphics-font-name-vectors.m`: actual glyph/units and unchanged PS controls for each generated font, then explicit absence or exact independently chosen original full-name string. Positive generated names were independently checked with host Fontconfig; both conflicting names remain present in the preference vector. No candidate runtime results are claimed.
- `freetype-font-name-reference.c`: original host-only public FreeType query for the explicit open Type1 input, independently compiled with `cc $(pkg-config --cflags freetype2) tests/freetype-font-name-reference.c $(pkg-config --libs freetype2) -o /scratch/reference`; no guest or CoreGraphics implementation is used.
- `make-type1-name-vector.py`: modifies one same-length byte in an explicit open URW PFB clear FontInfo full-name string; encrypted glyph data and segment lengths are preserved.
- `coregraphics-type1-font-names.m`: open NimbusSans-Regular.pfb, actual non-SFNT metrics, distinct PS/FontInfo names and ownership after pool/provider destruction. Exact Type1 FontInfo full_name independently queried with an original native FreeType public-API reference: Nimbus Sans (Fontconfig displays Nimbus Sans Regular, which is a derived display label and is not substituted for the actual FontInfo field).

Production O2Font.m and O2Font_freetype.m compile with the actual existing Onyx2D recipes into isolated x86_64+i386 fat objects. Original fixture TUs compile independently against Foundation/CoreGraphics; no candidate guest, other-platform backend runtime, native Mac naming equality or complete descriptor qualification is implied. Metadata-only candidate runtime and subsequent CoreText-target baselines remain coordinator-owned gates.
