Apple public class/property docs (rung3) define NSScrubberImageItemView:NSScrubberItemView with copy NSImage content, strong readonly NSImageView and alignment; source reuse is existing real NSImage/NSImageView/NSView (rung2). https://developer.apple.com/documentation/appkit/nsscrubberimageitemview . No Apple binary/SDK/private archive schema inspected. Initial center/up-or-down-proportional fit/noneditable/no-border choices are explicit compatible project policy, not measured native defaults.

The actual child is owned, attached once, fills bounds on resize/layout/bounds changes and remains publicly configurable. Image setter copies before replacing and releases temporary ownership; getter reflects actual child, alignment forwards. Lifetime cleanup balances own retain plus normal subview ownership, with initialized constructor failure cleanup. No alternate renderer, fake successful forwarding or whole Scrubber layout/data-source/selection-decoration engine is added. Existing base selected/highlighted storage/invalidation is inherited; Text content remains unqualified.

Own keyed view/state coding uses a project-prefixed child key, restoring the same super-decoded child rather than duplicating it; wrong type/other parent rejects explicitly. Missing key/legacy decode creates a genuine new child but does not promise native archive compatibility. Before the image codec integration, populated encoding explicitly raised before super writes because the then-existing NSImage encoder lost content. That historical guard covered normal image and inherited objectValue NSImage content; empty child/state roundtrip was only an intermediate gate. The codec integration enables the positive populated-image and object-value checks described below.

The canonical `appkit-scrubber-contract` image mode checks child hierarchy/layout, copied image ownership, resize, alignment and asymmetric bitmap rendering. Populated keyed coding must preserve image size and exact rendered pixels; empty keyed coding must retain state, unique child, alignment and layout. The `object-value-coding` mode checks the independently set child object value and its pixels through keyed coding. Lifetime checks retain the actual child independently, release the parent inside a nested autorelease pool, then check parent deallocation and a detached usable child after the pool drains; a witness checks child deallocation after the independent release and pool drain. The separate `lifetime` mode exercises the same ownership check. Earlier before-capable snapshots and observations remain historical evidence, not current expectations.
