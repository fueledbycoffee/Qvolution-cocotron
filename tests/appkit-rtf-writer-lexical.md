# Bounded lexical RTF writer regression

Public original NSAttributedString dataFromRange/documentAttributes fixture writes full, partial and empty ranges into caller-created fresh directory, refuses overwrite, verifies reopened byte equality and unchanged input. Large4096ASCII prefix crosses many256-unit chunks; suffix covers literal braces/backslash, Latin/nonspacing marks, supplementary signed-surrogate units, newline/tab/CR. No shared RTF reader validates writer output.

Run `python3 rtf-writer-lexical-oracle.py OUTPUT_DIRECTORY` independently on host after copying only own fixture outputs. Reused original public-format parser from earlier readiness work checks exact Unicode text, valid signed16 arguments and balanced groups. This is a narrow own oracle, not general RTF conformance or native-byte comparison. Root stage22 grouped writer creates231bytes but independent oracle rejects unsigned Unicode; original output also has unescaped braces. Static source underallocation risk is identified, no runtime memory corruption claimed. New large/slice/empty workload is prepared; candidate runtime pending.

Primary normative format: Microsoft [RTF1.9.1](https://officeprotocoldoc.z19.web.core.windows.net/files/Archive_References/%5BMSFT-RTF%5D.pdf), lexical escapes/control words, signed16 Unicode with fallback and character paragraph/tab controls. No sample implementation copied. Source fixes preserve all attribute/font-manager/color/paragraph/attachment behavior; those remaining gates stay independent. Range validity is checked by subtraction before arithmetic; source initialization consumes/releases self before range exception. No VLA/input-sized stack allocation remains in lexical method. Maximum per-unit ASCII length9 fits bounded output256*9; snprintf writes into separate16-byte temporary, never past chunk end.

Current verification: changed production NSRichTextWriter.m compiles with the existing AppKit fat x86_64/i386 recipe in an isolated output (exit0, eight existing warnings). Original public fixture compiles/links with the saved AppKit fixture recipe (exit0, two existing macro warnings). Root and independent source reviews approve this lexical change. The new large workload has no usable runtime-before result: its default-sandbox attempt produced no application output and timed out. Candidate runtime and independent writer-output oracle results remain pending; neither compilation nor historical grouped-writer failures establish the new workload result.
