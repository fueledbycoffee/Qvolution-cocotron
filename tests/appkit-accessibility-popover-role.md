# Public popover accessibility role data

Existing public NSAccessibilityConstants.h supplies NSAccessibilityRole as an NSString pointer; the actual LanguageAttribute and SwitchSubrole mappings provide positive controls. The new role was absent (clean-room rung2 header inspection).

[Apple public popover role documentation](https://developer.apple.com/documentation/appkit/nsaccessibility-swift.struct/role/popover?language=objc) specifies `extern NSAccessibilityRole const NSAccessibilityPopoverRole` (rung3). The public role is distinct from attributes and subroles. Its wire spelling is corroborated by primary API-client [AXSwift Constants.swift, pinned24b97ff4b018faa738aba52b5e6fe4cd28c80797 line122](https://github.com/tmandry/AXSwift/blob/24b97ff4b018faa738aba52b5e6fe4cd28c80797/Sources/Constants.swift#L122), `case popover = "AXPopover"`. This is an open-source client fact, not a native Mac measurement or Apple implementation inspection. Under the repository ladder the value remains an explicit conservative rung6 policy supported by that primary client. No other legacy role mappings are changed.

Original appkit-accessibility-popover-role.m loads real AppKit with Foundation+dlopen only, no GUI/args. Existing independently mapped LanguageAttribute and SwitchSubrole values must pass before the new lookup.
