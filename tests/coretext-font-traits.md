# Real symbolic font traits

Vendored CTFont/CTFontTraits headers already declare the public getter and copy dictionary (clean-room rung2). [Apple CTFontGetSymbolicTraits](https://developer.apple.com/documentation/coretext/ctfontgetsymbolictraits(_:)), [CTFontCopyTraits](https://developer.apple.com/documentation/coretext/ctfontcopytraits(_:)) and [kCTFontSymbolicTrait](https://developer.apple.com/documentation/coretext/kctfontsymbolictrait) specify the numeric symbolic value and dictionary role (rung3). Existing public [FreeType face/style flags](https://freetype.org/freetype2/docs/reference/ft2-face_creation.html#ft_style_flag_xxx) and [fixed-width macro](https://freetype.org/freetype2/docs/reference/ft2-font_testing_macros.html#ft_is_fixed_width) identify actual italic/oblique, bold and monospaced metadata.

This focused implementation maps those three actual provider bits. It reads only immutable face metadata initialized at font construction, calls no mutable/lazy FreeType API, and adds no AppKit dependency. It does not invent normalized weight, width, slant, stylistic class or unsupported symbolic capabilities. Unknown/non-FreeType face metadata returns no dictionary; invalid font returns zero bits/no dictionary. This is partial real traits, not complete native trait fidelity or a general FreeType rendering-lock fix.
