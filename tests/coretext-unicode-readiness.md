# Original Unicode and ideal horizontal metric readiness

Own-source public-API fixture, exact open DejaVu Sans Mono/Sans inputs. No Apple binaries, SDK internals, implementation code or native pixel snapshots used. Primary contracts: [glyph mapping](https://developer.apple.com/documentation/coretext/ctfontgetglyphsforcharacters), [ideal advances](https://developer.apple.com/documentation/coretext/ctfontgetadvancesforglyphs), [range fallback](https://developer.apple.com/documentation/coretext/ctfontcreateforstring), and public FreeType unscaled glyph metrics.

Build `coretext-font-reference.c` natively with pkg-config freetype2; supply Mono.ttf then Sans.ttf to emit the independent JSON oracle. This tool reads actual open-font cmap/design units through FreeType, not Cocotron. The checked JSON is reproducible from those exact installed DejaVu faces; fixture rejects different PostScript identity/units. Reference font bytes are not distributed here.

Run the actual-framework `coretext-unicode-readiness MODE MONO.ttf SANS.ttf REFERENCE.json [appkit]`, modes cmap/advance/fallback/clusters. Optional AppKit loads before fonts to exercise NSFont rather than KTFont. Root's stage22 before: cmap/fallback/clusters pass in both concrete paths; each advance mode fails48 checks after provider identity/units controls. All eight exact-prefix shutdowns succeed. Mono20pt ideal12.041015625 is rounded to12,17.5pt ideal10.535888672 to10; Sans20 A13.68164 to14. This proves the scoped ideal horizontal mismatch, not a Unicode packing/canonical-width/native-rendering issue.

Supplementary coverage accepts the actual glyph in either declared UTF16 slot and checks canaries; no native padding convention is invented. NFC/NFD widths are diagnostic only. Nominal combining advance may be nonzero in a monospaced face. The advance mode uses actual batches and NULL output summed calls against independent design units at20/17.5pt.

The correction reuses existing CG/O2 integer design-unit cache, scales actual CGFloat size, and supports scalable horizontal/default metrics in the existing identity-only constructor model. The same private batch loader builds scalable caches before face publication, with allocation bounds and transactional cleanup; no live per-query FreeType mutation added. Non-scalable/vertical legacy handling, requested matrix storage, variation fidelity, complete shaping, global face/font-library synchronization and UI workflows remain unqualified.

`coretext-advance-cost MONO.ttf SANS.ttf LARGE-CJK.ttc` measures10 provider constructions and30000 queried glyphs per input, reusing provider bytes. Internal observation reports ONLY owned advance-array payload bytes, not RSS/allocator overhead or total font memory. Exact selected PS/glyph count is printed; CJK input uses collection face0. It is a bounded timing workload, no speedup assertion or portable threshold. Parent and candidate measurements are required before assessing construction cost. Candidate runtime remains coordinator-owned.

Root review correction: no call to public STUB CTFontGetMatrix in the query guard. Existing constructors discard matrix requests; this narrow path uses that existing identity-only model explicitly. Any future real matrix storage/transform implementation must extend this path. No new matrix feature or global stub suppression.
