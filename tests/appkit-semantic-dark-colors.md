# Semantic catalog colors under dark drawing appearance

Apple's [Dark Mode HIG](https://developer.apple.com/design/human-interface-guidelines/dark-mode) specifies adaptive semantic roles with dimmer surfaces and brighter foregrounds, without requiring literal inversion. [Supporting Dark Mode in your interface](https://developer.apple.com/documentation/uikit/supporting-dark-mode-in-your-interface) includes macOS NSColor guidance: reusable semantic colors resolve when drawn, while explicit user content colors remain unchanged. These primary documents supply behavior/roles, not numerical native palette samples.

Original fallback policy: for DarkAqua/VibrantDark only, textBackgroundColor/controlBackgroundColor are neutral0.12, controlColor neutral0.18, textColor/controlTextColor/labelColor neutral0.92; opaque. This is deliberately a small Qvolution fallback palette, not measured/copied Apple values. windowBackgroundColor already aliases controlColor. Aqua retains each existing backend value; no global appearance is changed. High-contrast/unknown appearance names, selections, menus, secondary labels and literal control gradients remain unchanged in this first scoped feature. This is not complete dark mode or high-contrast/vibrancy rendering support.

The shared NSColor_catalog initializer wraps backing colors for those six System roles with existing NSColor_dynamic. Catalog identity and names remain intact; no new public API or subclass is introduced. Existing CGColor/setFill/setStroke/conversion forwarding resolves the dynamic backing. Non-System catalogs, unknown keys and explicit fixed colors do not enter this role mapping. Copying a color does not resolve it prematurely. CGColor itself remains a snapshot, as documented.

Build `appkit-semantic-dark-colors.m` linked with AppKit/CoreGraphics; run with no arguments under a real backend (NSDisplay existing backend reference is used). It retains five catalog colors across the creation autorelease pool and paints original1x1 CPU pixels via setFill and color-space conversion under light/dark/nested-light scopes. Aqua pixels must equal backend raw-role colors, conversions agree, cached colors change with semantic foreground/surface polarity and restore deterministically. Fixed content and non-System role-named catalog controls remain unchanged. Contrast/polarity thresholds are broad original regression criteria, not exact Apple pixels or a comprehensive accessibility audit.

Programmatic NSTextView still initializes a literal white background/black caret; legacy NSGraphicsStyle still paints several literal gradients. These require separately tested consumer changes; no explicit document or user-selected colors are rewritten here. System preference portals/default appearance remain separate.

Separate `appkit-semantic-control-surface.m` paints retained actual NSScrollView/NSClipView default backgrounds and public controlBackgroundColor with the semantic text foreground. It catches the otherwise mismatched bright-text/white-control-surface pairing. Both tests link AppKit/CoreGraphics and have no arguments.
