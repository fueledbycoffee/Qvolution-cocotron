# Real UI-role font selection

## Interface/demand and explicit policy

Primary [Apple function docs](https://developer.apple.com/documentation/coretext/ctfontcreateuifontforlanguage(_:_:_:)) specify a retained nullable UI-role font, size0 chooses the role default, and NULL language uses system language. Existing vendored CTFont.h defines enum values. Primary Qt[6.11.2 qcoretextfontdatabase.mm](https://github.com/qt/qtbase/blob/v6.11.2/src/gui/text/coretext/qcoretextfontdatabase.mm) fontTypeFromTheme/descriptorForFontType require11 unique roles: system,menuItem,emphasizedSystem,toolTip,windowTitle,smallSystem,pushButton,smallToolbar,views,miniSystem,userFixedPitch. Existing menuTitle is also retained. Other enum roles/None/unknown remain unsupported, returningNULL.

Face/default-size policy is expressly project/rung6, NOT native Mac measurements. Host Fontconfig configured sans-serif or monospace supplies actual font files/indexes; emphasized requests actual bold. Sizes0:12pt normal/menu/title/button/views/fixed;10pt smallSystem/smallToolbar/toolTip;9pt miniSystem. These reuse existing AppKit project size conventions without invoking AppKit or adding a dependency/recursion. Finite positive caller size is preserved; negative/NaN/infinity reject. Language uses checked CFString→UTF8 (no embedded NUL) and typed FcLangSet/FC_LANG, NULL leaves configured language defaults. Empty/invalid conversion returnsNULL. No pattern-string interpolation/Apple face label/fake trait or requested-label identity.

Fontconfig ranks candidates; we select a real Unicode FT face with positive units-per-em/glyph count and required actual fixed-width/bold flags. Rank-only weight hints do not establish real traits. An initial native source test caught its best-ranked bold match lacking FT_STYLE_FLAG_BOLD; the implementation now walks untrimmed ranked candidates, because equal-character-coverage faces can differ in required traits. If no true supported face exists it returnsNULL. No synthetic bold or mono metadata. Bitmap-only zero-units faces remain unsupported by this UI path. Existing coverage path retains its first-match/mandatory-codepoint semantics; it shares only the factored actual file/index/Unicode FT loader. Ownership of matched patterns, fontsets, language sets and FT faces is explicit.

Actual font identity is a separate FreeType PS/full-name metadata prerequisite; request aliases are never substituted for provider names. This commit neither merges that independent draft nor changes name/trait/descriptor implementations. No host settings/font files modified.

Malformed UTF16 conversion is additionally checked when the CFString constructor permits such a value; that conditional branch is not a blanket malformed-string qualification. No native role face/size or localization visual identity is asserted. Guest candidate and existing fallback regressions remain coordinator gates.
