# Normalized real-font descriptor

Existing vendored CTFont/CTFontDescriptor headers and dictionary-backed descriptor constructor were inspected first (clean-room rung2). [Apple CTFontCopyFontDescriptor](https://developer.apple.com/documentation/coretext/ctfontcopyfontdescriptor(_:)) specifies an owned normalized descriptor sufficient to recreate a font (rung3). The implementation reuses actual name/family/size/display/traits/cascade getters and CTFontDescriptorCreateWithAttributes; it does not introduce an AppKit dependency or requested-label substitute.

Actual CG PostScript metadata is required. If absent, return NULL rather than a fabricated empty descriptor that would silently recreate Helvetica. Available name/PostScript name, family, numeric size, display name, real supported symbolic traits and explicit caller cascade are copied into the existing immutable descriptor representation. Each copied value and construction state is released through @finally even when insertion or descriptor construction throws. The existing public type-ID contract is used; native descriptor object layout/identity is not asserted.

This does not add matrix/variation/feature storage or global default cascade fidelity: existing font constructors ignore or do not preserve those fields. Unsupported attributes are absent, not guessed. Face styles are limited to the separately implemented real bold/italic/monospace bits. General provider fonts with no real PS identity remain unsupported rather than pretending to be recreatable.

Original `coretext-font-descriptor.m` uses an explicit open BoldOblique provider and the PUBLIC descriptor constructor for input settings. Actual PS/family/metrics/glyph controls precede the target. It then checks owned descriptor/type, PS/family/display names, precise numeric size, bolditalic traits, explicit copied cascade after source-array mutation, independent attribute-copy mutation and lifetime after original font/provider/creation pool destruction. Recreation must preserve PS identity, size, ascent, glyph ID and cascade; those assertions are not weakened to accept a substituted regular face.

`appkit-coretext-font-descriptor.m` runs exactly that contract after loading actual AppKit before the first font and independently verifies NSFont concrete-class construction. `coretext-font-metadata.m` supplies the three-font regular/bolditalic/mono public metadata regression. It is included here after the prerequisite traits/Name commits; it is not a descriptor-pass claim.

Metadata-only coordinator stage18 proper descriptor runs (standalone and AppKit) reach the intended nil normalized-descriptor stub after input controls, exit1/shutdown0. Earlier pre-metadata input-identity failures are not target proof. The separate traits/Name/combined metadata/bridge gates pass in coordinator stage19; descriptor candidate has not yet run. Actual CoreText production recipe compiles x86_64+i386 fat; all original TUs compile independently.

Roundtrip still requires the separately delegated PostScript font-name resolver correction: old Fontconfig family lookup can substitute a regular face for a PostScript request. No descriptor recreation, vendor crash cause, all-font/native metadata fidelity, GUI or app qualification is inferred until the full preserved candidate gate actually passes under the coordinator runtime.
